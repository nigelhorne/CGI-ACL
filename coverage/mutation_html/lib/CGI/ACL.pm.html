   88: =head1 SYNOPSIS
   89: 
   90: CGI::ACL controls who can run your CGI script.  You build a set of rules
   91: and then call C<all_denied()> on every request.  If it returns C<1>,
   92: send an error response or redirect; if it returns C<0>, allow the request.
   93: 
   94: Rules can be stacked in any order using method chaining.  An unrestricted
   95: object (no rules added) allows everything.
   96: 
   97: =head2 Block all cloud-hosted visitors
   98: 
   99: The simplest use case -- no country list or lingua object needed.
  100: 
  101:     use CGI::ACL;
  102: 
  103:     my $acl = CGI::ACL->new()->deny_cloud();
  104: 
  105:     if ($acl->all_denied()) {
  106:         print "Content-Type: text/plain\n\n";
  107:         print "Automated cloud traffic is not permitted.\n";
  108:         exit;
  109:     }

  217: =head1 COMMON PITFALLS
  218: 
  219: The following mistakes are easy to make.  Read this section before filing
  220: a bug report.
  221: 
  222: =head2 allow_country alone has no effect
  223: 
  224: C<allow_country()> only restricts access when default-deny mode is active.
  225: Default-deny mode is activated by C<deny_country('*')> or
  226: C<deny_all_countries()>.  Without it, C<allow_country()> is silently
  227: ignored and everyone is still allowed.
  228: 
  229:     # WRONG -- this allows everyone; allow_country is ignored
  230:     my $acl = CGI::ACL->new()->allow_country('US');
  231: 
  232:     # RIGHT -- deny all countries first, then add permitted ones
  233:     my $acl = CGI::ACL->new()->deny_all_countries()->allow_country('US');
  234: 
  235: =head2 deny_cloud overrides allow_ip
  236: 
  237: Cloud detection has the highest priority.  An IP address that is listed
  238: in C<allow_ip()> is still blocked if its reverse DNS resolves to a cloud
  239: provider hostname.  This is intentional: cloud IPs can be reassigned, so
  240: the rDNS check is more reliable than the IP address alone.
  241: 
  242:     # This STILL blocks the IP if it is a cloud host
  243:     my $acl = CGI::ACL->new()
  244:         ->deny_cloud()
  245:         ->allow_ip('198.51.100.5');   # blocked if rDNS says EC2
  246: 
  247: =head2 Localhost is not automatically allowed
  248: 
  249: Once any restriction is set, C<127.0.0.1> is subject to the same rules
  250: as any other address.  If you need to allow local access (for example,
  251: a health-check endpoint), add it explicitly.
  252: 
  253:     my $acl = CGI::ACL->new()
  254:         ->allow_ip('127.0.0.1')   # must be explicit
  255:         ->deny_all_countries()
  256:         ->allow_country('US');
  257: 
  258: =head2 Forgetting the lingua argument
  259: 
  260: When country restrictions are active and C<all_denied()> is called without
  261: a C<lingua> argument, the module emits a C<carp> warning and denies the
  262: request.  Always pass a C<CGI::Lingua> object when country rules are in use.
  263: 
  264:     # WRONG -- will carp and deny every request
  265:     my $acl = CGI::ACL->new()->deny_all_countries()->allow_country('US');
  266:     $acl->all_denied();
  267: 
  268:     # RIGHT
  269:     my $lingua = CGI::Lingua->new(supported => ['en']);
  270:     $acl->all_denied(lingua => $lingua);
  271: 
  272: =head2 VPN and proxy users bypass IP and country checks
  273: 
  274: A visitor who connects through a VPN, Tor exit node, or anonymous proxy
  275: will appear to come from the proxy's IP address and country, not their
  276: own.  CGI::ACL has no way to detect this.  Cloud blocking provides some
  277: mitigation for VPS-based proxies.
  278: 
  279: =head2 Country codes are case-insensitive but stored lowercase
  280: 
  281: C<deny_country('BR')> and C<deny_country('br')> are equivalent.  All
  282: country codes are stored in lowercase.  C<CGI::Lingua::country()> may
  283: return either case; C<all_denied()> normalises it with C<lc()> before
  284: comparing.
  285: 
  286: =head2 The DNS result cache is not shared between CGI requests
  287: 
  288: In traditional CGI (one process per request), the per-object DNS cache
  289: is destroyed at the end of every request.  The cache is only useful in
  290: persistent-process setups such as FastCGI, mod_perl, or Plack servers,
  291: where the same C<CGI::ACL> object survives across many requests.

 1640: C<_set_countries>, C<_get_param>) are not enforced as private with

 1642: C<t/extended_tests.t>, etc.) calls them directly by fully-qualified name to
 1643: exercise specific code paths.  The C<namespace::clean> pragma removes them
 1644: from the object's method dispatch table, and the C<_> naming convention
 1645: signals their internal nature.
 1646: 
 1647: =item *
 1648: 
 1649: Windows platforms do not support C<alarm()>-based timeouts.  DNS lookups on
 1650: Windows block synchronously for as long as the OS resolver takes.
 1651: 
 1652: =item *
 1653: 
 1654: An optional rate-limiting feature (to block brute-force attacks) has not yet
 1655: been implemented.  It would require persistent shared state (e.g. Redis or an
 1656: in-memory cache) beyond this module's current dependency set.
