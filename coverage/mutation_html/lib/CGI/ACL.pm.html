 1285: =head1 LIMITATIONS
 1286: 
 1287: =over 4
 1288: 
 1289: =item *
 1290: 
 1291: A VPN or anonymous proxy will likely bypass IP-based access control and may
 1292: defeat country detection as well.
 1293: 
 1294: =item *
 1295: 
 1296: Country detection relies on L<CGI::Lingua> and its underlying GeoIP database,
 1297: which must be updated regularly.  GeoIP databases are never fully accurate;
 1298: satellite and mobile networks in particular can be misattributed.
 1299: 
 1300: =item *
 1301: 
 1302: Cloud detection depends on provider-maintained reverse-DNS records.  A cloud
 1303: host whose PTR record does not follow its provider's naming convention will
 1304: not be detected.  Conversely, a legitimate host whose PTR record accidentally
 1305: matches a cloud pattern could be falsely denied.
 1306: 
 1307: =item *
 1308: 
 1309: DNS lookups are synchronous.  On non-Windows platforms a C<$DNS_TIMEOUT>-second
 1310: alarm prevents indefinite blocking, but under high resolver load that latency
 1311: can still affect every request for an uncached IP.  For persistent processes
 1312: (FastCGI, mod_perl) the built-in per-object cache (C<$CLOUD_CACHE_TTL> seconds)
 1313: mitigates this significantly.
 1314: 
 1315: =item *
 1316: 
 1317: The per-object DNS result cache is neither shared between processes nor
 1318: persistent across objects.  Under a pre-forking server each worker child
 1319: maintains an independent cache.
 1320: 
 1321: =item *
 1322: 
 1323: Private methods (C<_is_cloud_host>, C<_verified_rdns>, C<_rdns_forward>,
 1324: C<_set_countries>, C<_get_param>) are not enforced as private with
 1325: C<Sub::Private> because this module's white-box test suite (C<t/function.t>,
 1326: C<t/extended_tests.t>, etc.) calls them directly by fully-qualified name to
 1327: exercise specific code paths.  The C<namespace::clean> pragma removes them
 1328: from the object's method dispatch table, and the C<_> naming convention
 1329: signals their internal nature.
 1330: 
 1331: =item *
 1332: 
 1333: Windows platforms do not support C<alarm()>-based timeouts.  DNS lookups on
 1334: Windows block synchronously for as long as the OS resolver takes.
 1335: 
 1336: =item *
 1337: 
 1338: An optional rate-limiting feature (to block brute-force attacks) has not yet
 1339: been implemented.  It would require persistent shared state (e.g. Redis or an
 1340: in-memory cache) beyond this module's current dependency set.
